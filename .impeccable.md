## Design Context

### Users
Smart contract developers using a focused workbench to inspect contract ABIs, query read methods, and send write transactions during development.

### Brand Personality
Plain, precise, and calm. It should feel like a dependable utility (think block explorer "Read/Write contract" tabs or a browser devtools panel), not a marketing page.

### Aesthetic Direction
Light and dark themes with neutral grey surfaces, the system UI font, and monospace only for contract data. One blue accent for primary actions and links; green, amber, and red only for status. Small radii, thin borders, no gradients, glows, or decorative icons. Support keyboard focus and reduced motion.

### Design Principles
- Get the user to a working read/write surface with as few steps as possible.
- Show contract state directly (argument-free view functions are read automatically).
- Use progressive disclosure: functions start as one-line rows; rarely used options live under "More options".
- Write labels in plain sentence case; avoid uppercase eyebrow labels and jargon.
- Keep every core workflow usable on narrow screens.
