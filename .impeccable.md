## Design Context

### Users
Smart contract developers using a focused workbench to inspect contract ABIs, query read methods, and send write transactions during development.

### Brand Personality
Technical, precise, and calm. The interface should feel like a dependable instrument with clear state feedback rather than a marketing surface.

### Aesthetic Direction
Dark-first developer tooling with restrained blue, teal, amber, and coral signals on ink-black surfaces. Dense but breathable, with monospace reserved for contract data and a crisp sans-serif for navigation and labels. Support keyboard focus and reduced motion.

### Design Principles
- Make contract state and method state immediately scannable.
- Use progressive disclosure so each function starts compact and opens into a practical form.
- Keep visual hierarchy quiet, with color reserved for network identity, types, and status.
- Prefer explicit controls and useful empty states over decorative UI.
- Preserve responsive access to every core workflow on narrow screens.
